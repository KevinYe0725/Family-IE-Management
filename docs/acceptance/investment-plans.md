# 定投计划：确认后记账

## 产品行为

入口：投资持仓 → 定投计划。提醒中心的定投来源链接直接到该页签；投资页汇总展示未完成期次。

1. 新建计划选择证券、每期金额、每周/每两周/每月、首次提醒日期、投资账户及提醒负责人。
2. 金额币种跟随证券，投资账户必须同币种。资金来源沿用投资账户关联的、已经初始化的具体现金账户；不执行自动换汇。
3. 到期仅生成待确认事项和站内通知，不扣款、不产生持仓。提醒日期采用上海日期；不是券商保证成交时间，休市可稍后实际操作再补记。
4. 确认弹窗填写实际数量、单价、费用、成交日期，核对现金余额，并确认已实际买入。计划金额允许与成交金额不同，不自动填入行情价。
5. 余额不足整笔失败。重复确认不产生第二笔成交；不同管理员并发操作也必须遵守同一期只确认一次。
6. 本期可跳过并填写原因，或两小时后/明天09:00提醒。下一期不会把旧期金额累加买入。
7. 编辑只影响后续生成项；暂停、结束保留已生成待办和历史。恢复不追补暂停期间期次。月底31日遇到短月使用月末，随后恢复原锚点。

## 历史及特殊情况

- 已确认期次保留最初实际金额，当前交易的更正/撤销状态同时可见；不会因撤销而重新自动扣款。
- 本期保存原始现金来源。若投资账户资金链接已变更，本期确认被拒绝，不静默换账户；核对后可按实际交易手工补录，并跳过本期待办，后续计划可重新编辑。
- 提醒负责人必须是活跃家庭成员；若之后离开家庭，不继续向其推送，也不静默换负责人。家庭管理员仍可查看待办并处理，应编辑计划重新指定负责人。
- 第一版只有站内通知，没有短信、邮件、微信或券商自动下单。

## 设计参考与复用

参考 [Binance Convert Recurring 官方流程](https://www.binance.com/en/support/announcement/detail/af6e55cae01d46f98a6520dfd9cd2252) 的金额、周期设置及确认摘要顺序；并非复制其自动交易行为。采用左右设置/摘要布局，小屏纵向排列，延续家账蓝色、石墨文字和浅灰背景。

复用现有 Semi Modal、TradeStockPicker、DateField、现金余额预览、通知持久化和投资账务引擎。不新增自动交易服务、组件依赖或第二套记账引擎。日期弹层挂载在模态对话框内部，Escape 先关闭日历。

## 验证边界

组件测试覆盖计划创建不交易、实际确认、余额失败保留输入、只读权限、单期跳过、撤销状态和提醒跳转，以及日期弹层。后端覆盖到期幂等、并发确认、资金回滚、月末规则、暂停与恢复、快照和权限。

最终验证（2026-09-09）：前端54个文件319项全部通过，类型检查与生产构建通过；后端非HTTP回归136个测试类699项中697项通过、2项MySQL条件测试跳过，无失败。前端在高并行争用时曾出现既有收支页面5秒超时，单文件及限制2个worker的全量重跑均通过，没有放宽断言或测试超时。生产构建保留既有大于500kB包体提示。

未将本地单元/MockMVC验证视为真实线上浏览器验收。没有在本地启动业务HTTP服务，也未清空用户数据。生产数据库需随正式部署执行 V39 迁移。

## 并发与验证限制

计划/期次修改、确认重试、生成器去重和通知身份读取采用锁取得后的当前读取，避免MySQL REPEATABLE READ旧快照导致已跳过期次被确认、已结束计划被重启。GET保持只读。独立复审通过；H2回归不能证明MySQL RR实机行为，本轮未启动MySQL。

本地排除会启动真实HTTP的Smoke、RegistrationRequestBodyLimit与EncodedAuthenticationFilter集成测试；CI流程未删改，部署前仍需由CI检查入口及生产环境。

## 实现取舍

- 沿用投资账户关联的现金来源，不另造独立扣款接口；若需要每一期任选不同资金账户，需扩展既有投资交易的资金来源契约。
- 上述真实HTTP测试留给CI；成本是本地交付不等于部署验收。
- 将既有行情时钟偏移测试夹具改为跨越17:30发布缓冲，而非午夜；不改变行情生产实现，仍断言实际时钟未到发布时点时应拒绝当天日线。
