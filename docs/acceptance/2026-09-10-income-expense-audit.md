# 收支一致性修复与实机验收

## 范围与口径

- 首页、收支明细和年度收支：共用收支记录的金额与发生日期，贷款现金还款包含本金和利息；买方直接代偿不是家庭现金支出。
- 费用预算：按账本费用计算，还款本金不占费用预算。与收支记录不同的指标明确称为“费用”。
- 资金流水：展示放款、资产与投资买卖、还款、账户互转等实际现金账户变动，保留原币，不把期初余额当作本期收入。
- 金额计算用精确十进制；外币使用入账历史汇率。缺少汇率不得当零。
- 测试仅操作课程项目的模拟账目，不涉及真实银行或证券交易；保留现有用户数据。

## 第四轮确认接口说明

- `GET /api/recurring-rules` 和发生项列表返回 `confirmationToken`。它是规则语义指纹，不是登录或授权凭据，不包含调度器推进的下次日期。
- 单笔新入账提交 `{ "amount": "12.00", "confirmationToken": "用户核对的规则标识" }`。
- 批量新入账提交 `occurrenceIds` 以及按发生项 ID 索引的 `confirmationTokens`。任一待入账项目失配，整批回滚。
- 不带标识的旧页面不能新增入账，应刷新页面重新核对。已经成功入账的无请求体重试仍可返回原记录，不新增扣款。
- 继续执行既有家庭、确认人、余额、来源唯一性与幂等校验；没有新增数据库迁移。
- 本地：5 个相关后端类共 71 项通过；前端 75 文件/434 项通过；类型检查与构建通过；第四轮代码复核通过。
