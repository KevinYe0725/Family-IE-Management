# Stage 2 Loans, Notifications, and Consolidated Reporting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add loan schedules and idempotent repayments, a unified reminder center, daily net-worth snapshots, and consolidated household asset/debt/budget analysis.

**Architecture:** Loan calculations are pure and deterministic; persisted installment schedules are historical commitments. Confirmation locks a schedule row and atomically creates one ledger transaction, reduces principal, and resolves a notification. Notifications and snapshots are idempotent derived data generated by scheduled application services.

**Tech Stack:** Java 17, Spring Boot 4.1.1, Spring Data JPA, Flyway, Spring Scheduling, H2, JUnit 5, MockMvc.

**Spec:** `docs/superpowers/specs/2026-09-02-family-finance-stage-2-design.md`

## Global Constraints

- Plans 1–3 are prerequisites.
- Loan principal/interest/payment values use integer cents; rates use bounded BigDecimal with explicit scale.
- Confirming recurring or loan items must be idempotent and cannot create duplicate ledger transactions.
- Only owner/admin manages loans; assigned members may confirm their own due items.
- Notifications and snapshots use unique natural keys and are safe to regenerate.
- Reporting never double-counts financial accounts, assets, investments, or liabilities.

## Plan API Contracts

- `GET|POST /api/loans`
- `PATCH /api/loans/{id}`
- `GET /api/loans/{id}/schedule`
- `POST /api/loan-installments/{id}/confirm`
- `POST /api/loans/{id}/prepay`
- `GET /api/notifications`
- `POST /api/notifications/{id}/read`
- `GET /api/net-worth`
- `GET /api/debt-analysis`
