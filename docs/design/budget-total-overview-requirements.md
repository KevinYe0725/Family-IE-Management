# 预算管理重构 · 需求汇总文档（月度总预算 + 分类/成员双层预算）

- 工作分支：`feature/budget-total-overview`（基于基线 `main` `07717aa` 创建）
- 状态：需求已确认，待细化实现
- 范围：仅预算管理模块（含必要的前置关联改动，见 §8）

---

## 1. 背景与问题

现有预算模型的问题：

1. **预算范围重叠导致总额失真**：`TOTAL / CATEGORY / MEMBER` 是同一笔钱的三种切法，金额互相包含。若把“家庭总预算”与下方子预算同时展示，会出现“子预算之和超过总预算”的荒谬观感，让总预算失去意义。
2. **成员维度过粗**：`MEMBER` 是一个“该成员全部支出”的聚合预算；而现实中不少支出属于全家（当前每笔收支必须归属某个具体成员，缺少“全体”归属）。
3. **预算只能事后看数字**：看不到“已用预算由哪些支出构成”（无下钻）；每月的预算需逐条新建，无法延续/复用。
4. **记账与预算脱节**：记支出时无法感知该笔是否会推高/突破某条预算。

## 2. 目标模型（核心口径，已确认）

### 2.1 月度总预算成为唯一权威总额

- 预算管理页顶部出现“月度总预算”设置区（每户每月一个值）。
- **“新建预算”中移除“家庭总预算（TOTAL）”选项**；存量 `TOTAL` 预算行迁移删除（见 §9）。
- 总预算的“已花费”= 当月全部已入账费用（沿用现 TOTAL scope 的花费口径：含已入账费用、投资及处置损失、单列手续费；不含偿还本金、资产/证券购入、互转、非现金估值）。

### 2.2 预算行三种形态（分类为主，成员是标签/观察线）

| 形态 | 存储含义 | 命中口径 | 是否进入总预算“已分配”池 |
|---|---|---|---|
| 分类预算 `(C, 无成员)` | 分类 C | **C 分类所有支出**（含任意成员与“全体”） | ✅ 进池（硬预算层） |
| 成员预算 `(无分类, M)` | 成员 M | **M 成员全部支出**（观察线） | ❌ 不进池 |
| 分类+成员预算 `(C, M)` | 分类 C 且成员 M | **C 分类中 M 的支出**（观察线） | ❌ 不进池 |

- 三种形态外不再有别的范围；“家庭总预算”不再作为预算行存在。
- **进池规则**：只有“无成员的分类预算行”的金额参与 `Σ(已分配) ≤ 总预算` 的硬约束；**一切含成员的项都是观察线，不计入总览条的“已分配”**，因此成员行不会污染总额、也不会让总预算显得无意义。
- 同一笔支出可同时命中多条不同形态的行（例：张三在餐饮消费 500 → 命中 `(餐饮,无成员)`、`(张三,无成员)`、`(餐饮,张三)` 各自独立统计），这是多维视图、不是 bug；**任何“求和尺子”只允许在同一维度内相加**（分类维、成员维不能交叉求和进总览条）。

### 2.3 总览条的两把“尺子”

- **总预算**：顶部唯一权威值（用户可设置/修改）。
- **已分配**：`Σ(无成员分类预算行金额)` —— 唯一受“≤ 总预算”硬约束的量。
- **实际总支出**：当月全部已入账费用（可与总预算无关地超过，仅作健康度展示）。

### 2.4 双向约束（防“总预算没意义”的机制）

- 方向一（设子预算）：新建/上调“无成员分类预算行”若导致 `Σ(已分配) > 总预算` → **拒绝保存**，提示“已超过月度总预算：请先调大总预算，或缩减/停用部分分类预算”。
- 方向二（设总预算）：把总预算调低到 `Σ(已分配)` 之下 → **拒绝保存**，提示“当前分类预算合计已超过该金额：请先缩减分类预算”。
- 成员观察线金额**不受上限约束**；但当观察线金额或“含成员预算合计”超过总预算时，界面温和提示“成员预算为观察线，不占家庭总预算额度”。

### 2.5 预算备注（新增需求）

- 每条预算（三种形态均可）可填写**备注**，纯文本，上限 200 字（如“五一假期调高”“孩子开学季”）。
- 备注在预算卡上以小字展示；进入修订记录可追溯（见 §3.3 口径）。

## 3. 功能需求

### F1 月度总览条（KPI 汇总）—— 页面顶部

位置：预算管理页顶部（“费用预算”标题下方、月份选择器/选项卡上方）的横条区域。

内容与交互：
1. **总预算设置**：显示当月总预算值与“设置/修改”入口（金额 + 生效日期即当月）。遵循 §2.4 双向约束。
2. **两把尺子**：总览条下方展示
   - “已分配预算条”：`已分配 = Σ(无成员分类行金额)`，占总预算的比例；
   - “实际总支出条”：当月实际费用，占总预算的比例（可超 100%，超时红色健康度提示）。
3. **KPI 数字**：总预算 / 已分配 / 剩余可分配（= 总预算 − 已分配）/ 实际总支出 / 预算行数（分类预算数）/ 超支项数与接近项数（计数口径：无成员分类行按硬预算状态；含成员观察线单独标注，如“2 条观察线超支”）。
4. **冲突/健康提示**：
   - 分配超出时（理论上被约束阻止，出现即视为异常/遗留数据）标红并提示调整；
   - 观察线合计超总预算时黄色提示“成员观察线不占额度，但合计已超过总预算，请留意”。
5. **未设置总预算时的形态**：总览条仍显示“实际总支出”，提示“尚未设置本月总预算”；设置后激活完整 KPI。

### F2 月份快捷切换 + 快捷操作

- 月份选择器旁增加：`◀ 上月 / 下月 ▶`、`回到本月`。
- 同区域提供快捷操作按钮：**复制上月预算到本月**（见 F5）、**应用预算模板**（见 F5）。
- 月份切换后总览条、预算卡、下钻、导出均跟随所选月份。

### F3 预算备注

- 新建/编辑预算抽屉内增加“备注”输入框（≤200 字，选填）。
- 预算卡上小字展示备注；悬停/截断处理。
- 修订记录：备注变更需要可追溯——修订记录除金额变化外，也记录“范围/备注”变化（旧 → 新）；若修订记录噪音过大可降级为仅记录金额与范围变更（实现时敲定，默认：记录，含 old/new 备注）。
- 复制下月与模板应用时**备注随行一起复制**。

### F4 预算执行“下钻明细”

- 每条预算行可打开“明细”抽屉/列表，展示**本月命中该条预算口径的支出逐笔清单**：日期、金额、分类、成员（含“全体”）、商家/备注、来源类型。
- 命中口径与 §2.2 一致（分类行含子分类归并 rollup，规则见 §4）。
- 分页加载；对“无成员分类行”与“含成员观察线”均可下钻；同一笔支出出现在多条命中行中是正常的。
- 可从明细反查对应收支（跳转收支页并按条件预筛）。

### F5 预算复制 / 批量生成下月 / 预算模板及一键应用

1. **复制到某月**：把源月所有“有效（active）行”复制到目标月，连同金额、形态、备注。
   - 默认参数：源月 = 当前查看月的上月；目标月 = 当前查看月；提供参数化支持任意 from/to。
   - 冲突处理：目标月已存在同形态同唯一键行 → **跳过并给出报告**（“已跳过 N 条：目标月已存在”）；支持“覆盖”选项（停用目标月同键行并新建？—— 实现细节：提供 `skip | overwrite` 两档，默认 skip）。
   - 范围选项：默认复制全部有效行；可选“仅无成员分类预算（不含观察线）”。
2. **预算模板**：
   - 模板 = 一整套预算行的可复用配置（形态、金额、备注；不含月份；不含已停用行）。
   - `保存为模板`：从某月整套预算另存（命名模板，如“日常月份”“旅行月”）。
   - `应用模板`：把模板行批量落到所选月份，冲突行跳过并报告（同复制规则）。
   - 模板属于家庭级资源，管理员可维护（命名、删除）。

### F6 预算与记账的联动提醒

- 在“记一笔 / 编辑收支”抽屉中，当用户选定**分类与成员（含全体）**后：
  - 若系统存在会命中该笔支出的预算行，提示该笔支出将如何影响：如“餐饮预算将用至 92%（超支）”“张三观察线将超支 ¥200”。
  - 依据：先计算该行当前已用 + 本笔金额 → 状态/使用率。
  - 仅提示、不阻断保存（与现有资金缺口提示同风格，复用/扩展 `PaymentPreview` 结构）。
- 需要轻量只读接口：按 (分类, 成员) 查询当月命中行及当前已用（见 §7）。

### F7 预算导出 CSV

- 导出所选月份的预算与执行：列 = 月份、类型（分类预算/成员预算/分类+成员）、分类、成员标签（含“全体”）、金额、已用、剩余、执行率、状态、备注。
- 文件名如 `budget-YYYY-MM.csv`；与现有收支 CSV 导出模式一致（仅导出当前家庭数据）。

### F8 收支明细的成员增加“全体”（前置关联需求）

- 背景：每笔支出不一定有具体对象，可能是全家支出；“成员是标签”的预算模型需要“全体”作为合法归属值。
- 需求：收支新增/编辑的“成员”选择中增加“**全体（家庭共同）**”选项；历史报表/预算命中按 §2.2 规则把“全体”作为独立值参与。
- 实现建议（实现时二选一，推荐前者）：
  1. `financial_transactions.member_id` 允许为 NULL，NULL = 全体（账务层已有 null → “家庭共同”的展示语义，见 `LedgerReportingService`）；需迁移放宽 NOT NULL 并核对所有按 member 联表的查询/统计。
  2. 或为每户引入固定虚拟成员“全体”（id=0 或专用行），不改表约束但需处理其联动（成员删除等边界）。
- 依赖关系：F8 应先于或与预算新模型同批上线（预算“全体”标签依赖它）。

## 4. 口径与规则汇总（实现时以此为唯一事实来源）

1. **形态唯一约束**（同月内）：`(C,无成员)` 唯一；`(C,M)` 同分类同成员唯一；`(无分类,M)` 唯一；跨形态允许并存。
2. **子分类归并（rollup）**：预算可建在一级或二级分类上；命中时对二级分类预算归并其子分类（沿用现有 `rollupCategories=true` 行为）；三种形态均适用。
3. **分类必须是支出分类**（沿用现状）；金额为正且 ≤ 99,999,999.99（沿用现状）。
4. **状态与展示**：沿用 `ON_TRACK / NEAR_LIMIT(80%) / AT_LIMIT / OVER_BUDGET`；进度条、颜色、停用（inactive）行不参与 `Σ(已分配)` 与统计。80% 阈值本期不动（可配置化列入后续候选）。
5. **修订记录**：每次金额/形态/停用变更保留不可变修订（沿用现状），另按 F3 记录备注变化。
6. **总览条统计范围**：计数默认 = 全部行（无成员行按硬预算、观察线单独分组标注）；求和只允许单维度。
7. **“全体”标签 vs 无标签的区别**（容易混淆，重点）：`(C, 无成员)` = 该分类全部支出（硬预算、进池）；`(C, 全体)` = 仅标“全体”的支出（观察线、不进池）。

## 5. UI 展示约定

- 总览条固定于页面顶部（F1）。
- 同分类下同时存在 `(C,无成员)` 与 `(C,M)` 时：成员行作为该分类的**责任子行**（缩进）展示，明确包含关系；并在成员行上标注“观察线 · 不占总预算额度”。
- 纯成员行 `(无分类,M)` 单独成组（“成员观察线”）或以列表项展示，同样带“观察线”标注。
- 预算卡保留：金额、已用、剩余、执行率、状态、备注（小字）、调整/停用/修订记录/明细入口。

## 6. 数据模型变更草案

- `budgets`：
  - 新增列 `note varchar(200) NULL`（备注）。
  - 语义收窄：`scope_type` 仅使用 `CATEGORY`（`member_id` 可空 = 无成员分类预算）与新增形态“成员观察线/分类+成员”（实现可选：沿用 `MEMBER`/`CATEGORY`+member 组合表达，或引入新 `scope_type` 枚举，保证三种形态能区分且唯一约束正确）。

## 7. 后端 API 变更草案

- `GET /api/budgets/usage`：行内新增 `note`、形态区分字段；聚合逻辑按 §2.2/§4 调整（Σ 只含无成员分类行）。
- `GET/PUT /api/budgets/total?periodMonth=`：读取/设置月度总预算（PUT 带版本号，双向约束校验）。
- `POST /api/budgets` / `PATCH /api/budgets/{id}`：接受备注与三种形态；无成员分类行受 `Σ ≤ 总预算` 约束。
- 新增 `GET /api/budgets/{id}/usage-entries?page=&size=`：下钻明细（按该行口径过滤的当月支出分页）。
- 新增 `POST /api/budgets/copy?fromMonth=&toMonth=`（参数：`scope=all|category-only`、`conflict=skip|overwrite`）：复制，返回“复制 N / 跳过 M”报告。
- 新增模板 CRUD：`GET|POST /api/budget-templates`、`DELETE /api/budget-templates/{id}`、`POST /api/budget-templates/{id}/apply?periodMonth=`。
- 新增 `GET /api/budgets/export.csv?periodMonth=`（F7）。
- 新增轻量只读：`GET /api/budgets/hit-check?periodMonth=&categoryId=&memberId=`（F6 记账联动用，返回命中行当前已用与状态）。
- 预算写操作建议补 `Idempotency-Key`（与账户/贷款/投资一致，减少双击重复）。

## 9. 存量数据处理与迁移

1. 存量 `TOTAL` 预算行：删除（连同其修订记录由外键级联或显式清理）；若当月存在有效 TOTAL 行，把其金额迁移为 `budget_monthly_totals` 的当月总预算（同一账户事务内完成）；无 TOTAL 行则总预算为空（未设置）。
2. 存量 `CATEGORY` 行（member 恒空）：语义不变（无成员分类预算，进池）。
3. 存量 `MEMBER` 行：语义不变，自然成为“成员观察线”（不进池）；**不需要改数据**，进池与否由服务按形态计算。
4. 存量收支的成员：全部为具体成员（无“全体”）；按 F8 实现方式决定是否补标/不处理（若采用 NULL=全体，历史数据保持不变，仍命中成员观察线，不再额外命中“全体”行——需在文档/提示中说明）。
5. 新增迁移 `V39`（MySQL `db/migration-mysql` 与 H2 `db/migration` 两份）：budgets.note、budget_monthly_totals（+修订表）、模板表、financial_transactions.member_id 放宽（若选 NULL=全体）。
