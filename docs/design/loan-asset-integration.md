# 贷款、资产、资金流水联动设计

基线：Stage 2 `c3af28e`。依据本任务已确认的设计，按三个独立可验收阶段交付。

## 第一轮：资金闭环（本轮实施）

- 新贷款实际到账与已有贷款期初分开；实际到账可少于本金，差额作为用户明确确认的预扣费用，单列费用，不记成收入。
- 本金仍按合同本金生成计划；还款沿用现有指定账户、原子扣款、重复提交保护、到期本息加额外还本和结清逻辑。
- 首页并列显示账内可用现金与净资产。现金来源为 CASH 子账户分录余额，只累计一次，不减未来债务；按同一估值汇率折算。未知期初/汇率不填零。
- 新增资金流水只读视角，读取现有账务来源和 CASH 分录，覆盖放款、还款、资产购置/处置、投资、互转。不是再造一份财务记录。
- 资金流水与现有收支记录分开展示。互转单列标记；没有真实现金腿的估值/直接购置不伪造现金流。
- 人民币贷款继续选择 CNY 子账户；不自动动用其他账户或自动换汇。保留全部现有贷款方法和历史。
- 页面保持现有居中弹窗、重要金额优先、少解释文字；计算说明置于详情。

## 第二轮：购置和关联（后续独立交付）

- 资产完整购置价、首付资金、贷款部分分开，默认值不能代替真实总价。
- 区分购置融资与抵押；资产可关联多笔贷款，参考净值不重复扣同一负债。
- 已经记录的放款/购买通过关联复用，不能再次生成现金和资产。
- 双向资产/贷款详情，保留合同识别、估值历史及权限。

## 第三轮：出售与债务处理（后续独立交付）

- 出售保留负债、出售款部分还贷、出售结清三种明确选择。
- 区分全部到账再还款与买方直接代偿后净额到账，不虚构账户现金。
- 余额不足补差、同一操作原子提交；已结清关联不阻止资产归档，历史关联不删除。

## 验证与发布约束

不清除旧数据；不将服务器参数、密钥或备份放入仓库。不运行本地 HTTP 启动测试。
第一轮完整通过类型、前端、MockMvc/H2 与迁移检查后，再交付发布；推送和部署须有用户授权。
