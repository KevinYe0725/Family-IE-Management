# 收支记录来源筛选 PRD

版本：1.0；日期：2026-10-30（北京时间）；业务决策来源：Codex 在用户委托的数据集设计范围内模拟 PM，未声称获得额外用户审批。

## 背景与现状

家庭成员在收支明细中需要将手工录入、周期账单和贷款产生的记录分开查看。目前账本提供月份、日期、收支类型、银行卡、账户、成员、分类和关键字筛选，列表、统计图表、CSV 都可使用现有条件，但无法按记录的来源筛选。后端 `financial_transactions.source_type` 已保存来源，V4 迁移对旧记录使用非空 `MANUAL` 默认值；响应的 `sourceType` 已是大写枚举。CSV 的真实入口为 `/api/export.csv`，不是 `/api/transactions/export`。

## 目标和非目标

在现有收支记录视图增加来源选择，使当前家庭的列表、全量统计和 CSV 导出筛选条件一致。沿用现有账务金额、货币换算、非现金记录、排序、权限与分页规则。不是资金流水筛选；不新增或改写记录，不修改记账规则、CSV 列、数据库结构、其他页面或角色权限。

## 用户、业务规则和需求

- 用户：已登录、可读取收支的家庭成员。来源筛选不扩大其权限；只能看到当前家庭的记录。
- R1：可选来源为 `MANUAL`（手工录入）、`RECURRING`（周期账单）、`LOAN`（历史贷款）、`LOAN_PAYMENT`（贷款还款）、`LOAN_PREPAYMENT`（贷款提前还款）。来源是数据库上已保存的精确值，历史贷款不包含其他两类。
- R2：`GET /api/transactions`、`GET /api/transactions/summary`、`GET /api/export.csv` 均接受可选查询参数 `sourceType`。缺省、空字符串或纯空白表示全部；非空值必须与上述大写枚举完全一致，前后空格、大小写变化、未知字符串不自动修正。
- R3：无效非空值返回 HTTP 400，JSON `error.code` 为 `VALIDATION_ERROR`，`error.fields.sourceType` 为 `来源类型无效`；不得退化成全部。其他字段的现有校验、认证与状态码不变。
- R4：来源与当前家庭、月份/日期、类型、银行卡、账户、成员、分类、关键字均取交集。列表排序和分页头保持原样；统计与 CSV 使用全部匹配记录，不只使用当前页。
- R5：账本「收支记录」视图增加有可访问名称「来源筛选」的下拉框，默认「全部」，其余选项与 R1 一一对应。选择后列表和统计请求及导出链接使用相同的 `sourceType`，选择「全部」时不传该参数；变更时回到第 1 页。
- R6：正在加载、出错和无匹配时沿用现有页面状态；无匹配的统计和 CSV 分别是现有空汇总和只有标题行的 CSV。保存收支后的筛选重置沿用现有清空行为。
- R7：不改变 `MANUAL` 与非手工记录的编辑、删除权限。无来源筛选时，结果维持原有行为，包括合法历史数据；不把潜在非法 NULL 数据归入任何具体来源。

## 验收标准

1. 使用同一家庭中不同来源、日期、账户、成员、分类和收支类型的区分数据，以及另一个家庭的同来源数据；验证各来源精确匹配、筛选条件相交、不泄露外部家庭。默认与空白均展示全部合法来源。
2. 对每个端点验证无效值、大小写不一致和带空格非空值为 R3 所述 400。各合法枚举均可查询，即使没有匹配记录。
3. 多于一页的匹配记录按既有次序分页，统计金额、条数与 CSV 覆盖所有匹配记录。核对不匹配来源和其他家庭记录不会进入统计与导出。
4. 在账本中先进入第二页再选来源；列表回到第一页，列表、统计和导出采用同一条件。切回全部时移除参数，其他现有筛选仍生效；验证选择无匹配时原有空状态、角色操作规则和金额货币展示未改变。
5. 自动测试使用隔离测试数据库与合成数据；测试结果为开发证据，独立 QA 执行及验收另行完成。

## 范围与风险

复用 `TransactionFilter` → `TransactionFilterParser` → `TransactionSpecifications`，避免在三个端点各自编写来源判断而产生偏差。源数据实际依赖现有迁移和约束；没有额外修复非法数据。汇总既有缺失汇率、非现金口径和 CSV 格式必须保留。现有 H2 测试与浏览器模拟不能单独证明 MySQL、生产环境或真实浏览器最终验收。
