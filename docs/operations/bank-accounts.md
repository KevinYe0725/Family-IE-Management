# 银行主账户使用与发布说明

## 用户操作

在账户管理中选择“新建银行卡”，填写卡名、银行和可选尾号，然后逐项添加人民币、港币、美元余额。每项输入实际期初余额和起始日期，确认后保存。银行卡只显示一张卡片，各币种余额独立。

已有卡通过“管理余额”添加币种、确认期初或编辑卡片资料。币种在系统支持范围内，未初始化的余额不能付款。贷款、实体资产和周期账单当前仍只使用人民币；此改动不增加外币贷款等业务。

记账时选择银行卡，已知业务币种自动匹配具体余额；普通收支及换汇需明确币种。匹配失败不会自动换卡、换汇或猜测期初余额。缺少币种可以在选择器内添加，保存后返回原表单。

整卡流水筛选使用 bankAccountId；具体币种筛选使用 accountId，两个条件同时出现时取交集。导出应用相同条件。

## 兼容边界

- 银行主账户不产生独立余额和分录，净资产继续只统计币种子账户。
- 原有 accountId、fundingAccountId、paymentAccountId 继续指向 financial_accounts 子账户。
- 原 /api/accounts 不混入父对象；/api/bank-accounts 独立返回主账户及子账户列表。
- V41 为旧 BANK 账户逐一建立父对象，保留子账户 ID、余额和历史。不按名称或尾号合并。
- 旧调用者创建 BANK 账户仍能工作，并自动得到一个单币种主账户。
- 主账户归档必须满足各币种余额为零、初始化已确认、无阻塞绑定；归档不删除流水。

## 发布与测试数据

本次开发不自动清空服务器数据。用户允许丢弃财务测试数据，但清理必须作为单独的一次性运维操作：先备份并验证备份可用，再暂停写入，清理关联财务数据和派生记录，保留用户、家庭、成员与权限，随后重新初始化。

不要把删除逻辑加入 Flyway，也不要在应用启动时重复清空。若不执行清理，兼容迁移仍应能保留旧账正常运行。

## 验证清单

本地实现验证：前端 60 个文件、360 项测试与构建通过；后端非 HTTP 启动类回归通过，独立复核涵盖主子账户边界、归档引用、幂等和筛选一致性。MySQL 实机迁移及公网界面验收尚未执行，不能将本地测试当成上线证明。

归档只检查未来付款依赖：投资资金绑定、未结束定投及待确认期次、有效周期规则、有效贷款付款账户。购入资产、历史放款等一次性来源不会阻止归档，相关历史外键仍保留。

- 创建一张含 CNY/USD 的卡，两个子账户 ID 不同，主账户相同。
- 重复请求不产生重复子账户或期初分录；同币种不能重复添加。
- 非家庭账户不可操作；普通成员不可管理银行卡。
- 美元不足但人民币充足时仍拒绝美元付款。
- 同卡换汇分开记录两边金额、费用，失败整笔回滚。
- 子账户更正、冲销和原有业务重试仍沿用原 ID。
- 整卡流水分页及 CSV 范围一致，不跨家庭。
- 总览不重复计算父对象，银行卡的折合金额不用于付款。
